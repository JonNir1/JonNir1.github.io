## Site Overview

This is **Jonathan Nir's personal academic website**, built on the [al-folio](https://github.com/alshedivat/al-folio) Jekyll theme. It is deployed to GitHub Pages at `https://jonnir1.github.io`. The `gh-pages` branch is auto-generated by GitHub Actions — all changes go to `main`.

## Commands

### Local Development (Docker — use this)

```bash
docker compose pull && docker compose up   # Start dev server at http://localhost:8080
docker compose up --build                  # Rebuild after dependency changes
docker compose down                        # Stop and free port 8080
```

### Code Formatting (mandatory before committing)

```bash
# First time only:
npm install --save-dev prettier @shopify/prettier-plugin-liquid
# Every commit:
npx prettier . --write
```

The `prettier.yml` CI workflow **fails PRs** if formatting is not applied.

### Build without Docker (legacy)

```bash
bundle install
pip3 install --upgrade nbconvert
bundle exec jekyll serve --port 4000       # http://localhost:4000
```

ImageMagick must be installed locally (`brew install imagemagick` / `apt-get install imagemagick`).

## Architecture

### Configuration Entry Points

- **`_config.yml`** — primary configuration: site identity, `url`/`baseurl`, feature flags (`enable_*`), Jekyll Scholar settings, plugin configuration. Feature flags live here (not in data files). `url`/`baseurl` must be consistent: personal site uses empty `baseurl`.
- **`_data/`** — structured data consumed by templates:
  - `socials.yml` — social media links (used in header/footer)
  - `cv.yml` — CV in RenderCV YAML format (preferred; auto-generates PDF via `render-cv.yml` workflow)
  - `coauthors.yml` — links coauthor names to their pages (for publications)
  - `venues.yml` — venue abbreviations shown on publication cards
  - `citations.yml` — citation counts fetched by `update-citations.yml` workflow
  - `repositories.yml` — GitHub repos displayed on the repositories page

### Content Collections

Content is organized as Jekyll collections:

| Directory | Purpose | Filename format |
|---|---|---|
| `_pages/` | Static pages (about, cv, publications, etc.) | `name.md` |
| `_posts/` | Blog posts | `YYYY-MM-DD-title.md` (required) |
| `_projects/` | Project showcase entries | `name.md` |
| `_news/` | Homepage announcements | `name.md` |
| `_teachings/` | Course pages | `name.md` |
| `_bibliography/papers.bib` | All publications (BibTeX) | — |

### Publications System

Publications are managed via `jekyll-scholar`:
- All entries in `_bibliography/papers.bib` using standard BibTeX plus al-folio custom fields
- Custom BibTeX fields: `abstract`, `pdf`, `code`, `html`, `preview`, `slides`, `poster`, `selected`, `award`
- `pdf` field resolves relative to `assets/pdf/`; `preview` resolves relative to `assets/img/publication_preview/`
- Author highlighting is configured in `_config.yml` under `scholar.last_name` / `scholar.first_name`
- `selected: {true}` in a BibTeX entry makes it appear on the about page

### CV System

Two formats coexist:
- **RenderCV** (`_data/cv.yml`) — YAML format; GitHub Actions (`render-cv.yml`) auto-generates a PDF to `assets/rendercv/`
- **JSONResume** (`assets/json/resume.json`) — standard JSON format
- `_pages/cv.md` frontmatter `cv_format` controls which renders: `rendercv` or `jsonresume`

### Template Layer

- `_layouts/` — page layouts (`about.liquid`, `post.liquid`, `bib.liquid`, `cv.liquid`, `distill.liquid`)
- `_includes/` — reusable components; `_includes/cv/` contains per-section CV renderers
- `_sass/` — SCSS; change `--global-theme-color` in `_sass/_themes.scss` to retheme; variables in `_sass/_variables.scss`

### CI/CD

Key GitHub Actions workflows (`.github/workflows/`):
- `deploy.yml` — builds with `JEKYLL_ENV=production`, runs PurgeCSS, pushes to `gh-pages`
- `prettier.yml` — enforces formatting; blocks PRs on failure
- `render-cv.yml` — regenerates CV PDF from `_data/cv.yml`
- `update-citations.yml` — updates `_data/citations.yml` with live citation counts

## Key Pitfalls

- **YAML special characters**: quote strings containing `:`, `&`, or `#` in `_config.yml`
- **`baseurl` must exist but be empty** for a personal site: `baseurl:` (deleting the key breaks asset URLs)
- **CSS/JS not loading after deploy**: incorrect `url`/`baseurl` pairing — clear browser cache after fixing
- **Prettier CI failure**: run `npx prettier . --write` before every commit
- **"Zero vectors cannot be normalized"**: blog post has no meaningful text content; add content or set `related_posts: false` in frontmatter
- **Never edit `gh-pages` branch** — it is fully overwritten by CI on every push to `main`
